Formularios en HTML

Los formularios son el mecanismo estándar de HTML para recibir información introducida o seleccionada por el usuario. Un formulario puede contener campos de texto, listas, casillas de verificación, botones de opción, selectores de fecha, controles para archivos y botones, entre otros controles.

HTML define la estructura, el significado y buena parte del comportamiento básico de estos controles. CSS permite controlar su presentación. El procesamiento de los datos enviados corresponde posteriormente al servidor o a código JavaScript cuando la aplicación requiere un flujo distinto al envío tradicional del formulario.

El elemento form

El elemento <form> agrupa controles relacionados y define cómo se enviarán sus datos. Para comprender un formulario conviene separar cuatro conceptos: el control que el usuario manipula, la etiqueta que explica su propósito, el nombre con el que se enviará el dato y el valor introducido.

El atributo for de cada label coincide con el id del control correspondiente. El atributo name identifica el dato cuando el formulario se envía.

id, name y value cumplen funciones diferentes

Atributo Función principal
id Identifica un elemento dentro del documento. Se utiliza, entre otras cosas, para asociar un label con su control y para seleccionarlo desde CSS o JavaScript.
name Define la clave con la que el control participa en los datos del formulario. Un control sin name normalmente no aporta una entrada al conjunto de datos enviado.
value Representa el valor actual o inicial del control, según el tipo de entrada. En botones de opción y casillas de verificación permite definir qué valor se enviará cuando estén seleccionados.
El atributo placeholder no sustituye a un label. El texto de ayuda desaparece cuando el usuario escribe y no constituye una asociación semántica entre la descripción y el control.

Envío de datos

Cuando se envía un formulario, el navegador construye un conjunto de pares nombre y valor a partir de los controles que participan en el formulario. Después codifica esos datos y genera una solicitud HTTP de acuerdo con los atributos definidos en <form>.

Atributos principales de form

Atributo Descripción
action URL a la que se enviará la solicitud. Puede apuntar a una ruta del mismo sitio o a otro recurso que acepte los datos.
method Método utilizado para enviar el formulario. Los valores habituales son get y post.
enctype Codificación utilizada cuando el método es post. Para enviar archivos se utiliza multipart/form-data.
autocomplete Indica si el navegador puede ayudar a completar los controles. Los controles individuales pueden especificar valores más precisos.
novalidate Desactiva la validación de restricciones del navegador durante el envío del formulario.

GET y POST

Aspecto GET POST
Ubicación de los datos Se incorporan a la URL como parámetros de consulta. Se incluyen en el cuerpo de la solicitud.
Uso habitual Consultas, filtros, búsquedas y operaciones que no pretenden modificar el estado del servidor. Creación, actualización y otras operaciones que envían información para ser procesada.
URL compartible Los parámetros forman parte de la URL y pueden guardarse o compartirse. Los datos no forman parte de la URL.
Datos sensibles No deben colocarse datos sensibles en la URL. Que los datos viajen en el cuerpo no los cifra. La confidencialidad en tránsito depende de HTTPS.
POST no es un mecanismo de cifrado. Para proteger los datos durante el transporte, la aplicación debe usar HTTPS. La validación y las decisiones de seguridad tampoco deben depender únicamente del navegador.

Controles que participan en el envío

El atributo name es fundamental para construir los datos del formulario. También existen estados que modifican la participación de un control.

Situación ¿Se envía?
Control habilitado con name Sí, si corresponde según su tipo y estado.
Control sin name No aporta un par nombre y valor.
Control con disabled No.
Control con readonly Sí. El usuario no puede modificarlo, pero su valor puede enviarse.
Checkbox no seleccionado No.
Radio no seleccionado No.

Envío de archivos

Un formulario que envía archivos debe utilizar method="post" y enctype="multipart/form-data". El atributo accept permite orientar al selector de archivos hacia determinados tipos, pero no reemplaza la validación del servidor.

<form action="/subir" method="post" enctype="multipart/form-data"> <label for="archivo">Documento:</label> <input id="archivo" name="archivo" type="file" accept=".pdf"> <button type="submit">Subir archivo</button> </form>

Controles de entrada

El elemento <input> cambia de comportamiento según el valor de su atributo type. Elegir el tipo correcto mejora el teclado mostrado en dispositivos móviles, aporta semántica y permite que el navegador aplique restricciones de validación apropiadas.

Entradas de texto y datos estructurados

Tipo Uso Observación
text Texto de una sola línea. Es el valor predeterminado de type.
password Contraseñas. Oculta visualmente los caracteres, pero no cifra el valor.
email Direcciones de correo electrónico. Realiza validación sintáctica básica. No comprueba que la dirección exista.
tel Números telefónicos. No impone un formato universal. Puede combinarse con pattern.
url Direcciones URL. El navegador verifica que el valor tenga sintaxis de URL.
search Campos de búsqueda. Su apariencia puede diferir ligeramente entre navegadores.

Campos ocultos

<input type="hidden"> permite incorporar un valor al envío sin mostrar un control en la interfaz. Que el campo sea invisible no lo convierte en un dato protegido. El usuario puede inspeccionar y modificar el HTML desde las herramientas del navegador, por lo que el servidor debe validar cualquier valor recibido.

Estructura semántica del formulario

label

Cada control que recibe datos debe tener una descripción comprensible. La asociación explícita entre label y control se establece haciendo coincidir for con el id. Esta relación mejora la accesibilidad y también permite activar o enfocar el control al seleccionar su etiqueta.

fieldset y legend

fieldset agrupa controles relacionados y legend proporciona el nombre del grupo. Son especialmente útiles en conjuntos de radio buttons y checkboxes porque aportan contexto al grupo completo.

select, option y optgroup

select permite elegir una o varias opciones predefinidas. option define cada opción y optgroup permite agrupar opciones relacionadas. Conviene establecer un value explícito cuando el texto visible no debe ser el dato que reciba el servidor.

datalist

datalist ofrece sugerencias para un input, pero no restringe el valor únicamente a esas sugerencias. El usuario puede escribir otro valor si el control lo permite.

textarea

textarea recibe texto de varias líneas. Su valor inicial se escribe entre la etiqueta de apertura y la etiqueta de cierre. Los atributos rows y cols pueden definir un tamaño inicial, aunque en una interfaz real suele ser preferible controlar el tamaño visual con CSS.

button

Para los botones de una interfaz moderna se prefiere normalmente el elemento <button> frente a <input type="button"> o <input type="submit">, porque permite contenido HTML y ofrece mayor flexibilidad de presentación.

Dentro de un formulario, un button sin type se comporta como un botón de envío. Cuando el botón no debe enviar el formulario conviene escribir explícitamente type="button". Los botones de tipo reset deben utilizarse con cuidado, ya que pueden borrar accidentalmente el trabajo del usuario.

Atributos de los controles

Atributo Función Aplicación habitual
placeholder Muestra una pista breve sobre el dato esperado. Entradas de texto y textarea.
required Impide el envío si el control requerido no satisface la condición de obligatoriedad. Controles que forman parte de la validación de restricciones.
minlength y maxlength Definen límites de longitud para texto. Campos de texto y textarea.
min, max y step Definen límites y granularidad. Números, fechas, horas y rangos.
pattern Define una expresión regular que debe satisfacer el valor. text, search, url, tel, email y password.
readonly Impide modificar el valor sin excluirlo del envío. Controles textuales compatibles.
disabled Deshabilita la interacción y excluye el control del envío. Controles temporalmente no disponibles.
multiple Permite seleccionar o proporcionar más de un valor cuando el tipo lo admite. file, email y select.
accept Indica tipos de archivo preferidos para el selector. file.
inputmode Orienta al navegador sobre el teclado virtual más apropiado. No añade validación por sí mismo. Entradas de texto en dispositivos con teclado virtual.
form Asocia un control con un formulario mediante el id del formulario, incluso cuando el control está fuera del elemento form. Controles cuya ubicación visual o estructural está separada del formulario al que pertenecen.

autocomplete

autocomplete no se limita a on y off. Los valores semánticos permiten indicar al navegador qué información espera cada campo. Esto facilita el autocompletado y puede mejorar la experiencia de uso, especialmente en formularios repetitivos.

Valor Dato esperado
nameNombre completo.
given-nameNombre de pila.
family-nameApellido.
emailCorreo electrónico.
telNúmero telefónico.
usernameNombre de usuario.
current-passwordContraseña actual.
new-passwordNueva contraseña.
En formularios de autenticación, los navegadores y gestores de contraseñas pueden ignorar autocomplete="off". Para una contraseña nueva es más informativo utilizar autocomplete="new-password".

Estilización de formularios

Los controles de formulario tienen estilos nativos definidos por el navegador y el sistema operativo. Es posible personalizar gran parte de su apariencia, pero conviene conservar señales de interacción reconocibles y estados de foco visibles.

Para alinear etiquetas y controles no es necesario utilizar tablas ni float. Flexbox permite construir la distribución directamente a partir de la estructura semántica del formulario.

Foco visible

El foco indica qué control recibirá la interacción del teclado. No debe eliminarse sin proporcionar una alternativa clara. La pseudoclase :focus-visible permite destacar el foco cuando el navegador determina que el indicador visual es necesario.

input:focus-visible, select:focus-visible, textarea:focus-visible, button:focus-visible { outline: 3px solid #C8AD55; outline-offset: 2px; }

Estados y pseudoclases de formularios

CSS puede seleccionar controles según su estado. Esto permite mostrar información visual sin agregar clases manualmente para cada cambio de estado.

Pseudoclase Selecciona
:focusEl elemento que posee el foco.
:focus-visibleEl elemento enfocado cuando corresponde mostrar una indicación visible de foco.
:requiredControles que tienen el atributo required.
:optionalControles que no son obligatorios.
:validControles cuyo valor satisface las restricciones aplicables.
:invalidControles cuyo valor no satisface alguna restricción.
:user-validControles válidos después de interacción relevante del usuario.
:user-invalidControles inválidos después de interacción relevante del usuario.
:checkedCheckbox, radio u opciones que se encuentran seleccionados.
:in-rangeControles cuyo valor se encuentra dentro de sus límites.
:out-of-rangeControles cuyo valor no satisface sus límites.
:disabledControles deshabilitados.
:read-onlyControles no editables por el usuario.
:user-valid y :user-invalid permiten retrasar la indicación visual hasta que exista interacción del usuario. Cuando se necesita compatibilidad con navegadores que no implementen estas pseudoclases, :valid y :invalid siguen siendo la alternativa básica.

Validación nativa del navegador

HTML incorpora un sistema de validación de restricciones. Antes de enviar un formulario, el navegador puede verificar condiciones derivadas del tipo de control y de atributos como required, minlength, maxlength, min, max, step y pattern.

La validación realizada por HTML se ejecuta en el cliente. Puede mejorar la experiencia del usuario y evitar envíos evidentemente incorrectos, pero no reemplaza la validación del servidor. El servidor debe considerar no confiable cualquier dato recibido del cliente.
Mecanismo Ejemplo Qué verifica
required <input required> Que el control obligatorio tenga un valor aceptable.
type="email" <input type="email"> Sintaxis básica de una dirección de correo electrónico.
minlength minlength="8" Longitud mínima del texto.
min y max min="18" max="100" Rango permitido para tipos compatibles.
pattern pattern="[0-9]{8}" Que el valor completo satisfaga una expresión regular.

novalidate y formnovalidate

novalidate en form permite enviar el formulario sin ejecutar la validación nativa. Un botón de envío también puede utilizar formnovalidate para omitirla únicamente cuando el formulario se envía mediante ese botón. Estos atributos no eliminan la necesidad de validar en el servidor.

Validación con pattern y expresiones regulares

El atributo pattern permite definir una expresión regular para validar valores de controles de tipo text, search, url, tel, email y password. En HTML la expresión debe coincidir con el valor completo del control, por lo que no es necesario agregar manualmente ^ y $ para exigir coincidencia total.

Elementos básicos de una expresión regular

Expresión Significado Ejemplo
[0-9] Un dígito entre 0 y 9. [0-9]{8} exige ocho dígitos.
[A-Za-z] Una letra mayúscula o minúscula del alfabeto latino indicado. [A-Za-z]{3} exige tres letras.
[^0-9] Un carácter que no pertenece al conjunto indicado. [^0-9]+ exige uno o más caracteres que no sean dígitos.
A|B Alternativa entre dos expresiones. (A|B)+ permite secuencias formadas por A o B.
{n} Exactamente n repeticiones. [0-9]{4}.
{n,m} Entre n y m repeticiones. [A-Za-z]{5,10}.
+ Una o más repeticiones. [A-Za-z]+.
* Cero o más repeticiones. [0-9]*.
? Cero o una repetición. -?[0-9]+ permite un signo negativo opcional.
