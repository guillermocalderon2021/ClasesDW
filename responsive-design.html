Qué significa que una interfaz sea responsiva

Una interfaz responsiva adapta su estructura, dimensiones, tipografía y medios al espacio disponible y a las capacidades del entorno de interacción. El objetivo no consiste en construir una versión para teléfono, otra para tableta y otra para computadora. El objetivo es construir una única interfaz que continúe siendo usable en un rango amplio de tamaños.

El diseño responsivo se apoya en tres ideas clásicas: layouts flexibles, medios flexibles y media queries. El CSS actual permite añadir una cuarta idea importante: componentes que pueden adaptarse al espacio de su propio contenedor.

Layout flexible

La estructura puede crecer, contraerse, envolver elementos y reorganizar columnas.

Medios flexibles

Imágenes, videos e iframes no deben desbordar su contenedor.

Media queries

Permiten modificar reglas cuando el viewport cumple determinadas condiciones.

Componentes adaptables

Las container queries permiten responder al espacio del componente y no solo al viewport.

Responsivo no significa eliminar todos los píxeles del CSS. Los porcentajes, fr, rem, vw y otras unidades relativas son útiles para dimensiones que deben adaptarse. Los píxeles siguen siendo apropiados para bordes, detalles pequeños y muchos puntos de corte. Lo importante es evitar depender de dimensiones rígidas para la estructura principal.

Viewport y píxeles CSS

El viewport es el área que el navegador utiliza para mostrar la página. En un documento diseñado para diferentes tamaños de pantalla debe declararse el viewport dentro de head. 

<meta name="viewport" content="width=device-width, initial-scale=1.0">

width=device-width indica que el ancho del viewport debe corresponder al ancho disponible del dispositivo expresado en píxeles CSS. Un píxel CSS es una unidad lógica y no necesariamente coincide con un píxel físico de la pantalla.

No se recomienda usar user-scalable=no ni limitar el zoom con valores pequeños de maximum-scale. El usuario debe conservar la capacidad de ampliar el contenido cuando lo necesite.

Unidades relacionadas con el viewport

Unidad Referencia Uso típico
vw 1% del ancho del viewport Dimensiones que deben crecer con el ancho disponible.
vh 1% de la altura del viewport tradicional Secciones relacionadas con la altura visible.
dvh 1% de la altura dinámica del viewport Interfaces móviles donde las barras del navegador aparecen o desaparecen.
vmin 1% de la dimensión menor del viewport Elementos que deben depender del lado más pequeño.

Construir una base fluida antes de crear breakpoints

Un diseño responsivo no debería depender de media queries para corregir cada tamaño posible. Primero se construye una base que pueda contraerse y expandirse por sí sola. Las media queries se añaden cuando la estructura necesita un cambio real de composición.

Reglas base recomendables

*, *::before, *::after {
  box-sizing: border-box;
}

img,
video {
  max-width: 100%;
  height: auto;
}

iframe {
  max-width: 100%;
}

body {
  margin: 0;
  overflow-wrap: anywhere;
}

box-sizing: border-box simplifica el cálculo de dimensiones porque width y height incluyen el padding y el borde. La regla sobre medios evita que un recurso intrínsecamente ancho desborde su contenedor. overflow-wrap ayuda con cadenas largas como URLs o identificadores.

Media queries

Una media query aplica reglas CSS cuando una condición del entorno es verdadera. Para responsive design, la condición más utilizada es el ancho del viewport. 

@media (min-width: 700px) {
  .contenido {
    display: flex;
    gap: 1rem;
  }

  .principal { flex: 2; }
  .lateral { flex: 1; }
}

En este ejemplo, la regla se activa cuando el viewport tiene al menos 700px de ancho. No es necesario escribir screen and cuando no se necesita distinguir entre tipos de medio.

Mobile first

En un enfoque mobile first, los estilos iniciales resuelven la presentación estrecha. A medida que aparece espacio adicional, se añaden mejoras mediante condiciones min-width. Esta estrategia reduce la cantidad de reglas que deben deshacerse en pantallas pequeñas.

Operadores y condiciones

Consulta Interpretación
@media (min-width: 700px) Viewport de 700px o más.
@media (max-width: 699px) Viewport de 699px o menos.
@media (min-width: 700px) and (orientation: landscape) Se cumplen simultáneamente ambas condiciones.
@media (max-width: 500px), (orientation: portrait) Se cumple al menos una de las condiciones.
La sintaxis moderna también permite consultas de rango como @media (width >= 700px). La forma con min-width y max-width sigue siendo válida y es útil para reconocer código existente.

Elegir breakpoints a partir del contenido

Un breakpoint no representa un modelo de teléfono ni una marca de tableta. Representa el punto en el que el diseño actual deja de funcionar correctamente. Por esa razón no conviene construir una tabla rígida de resoluciones para teléfonos, tabletas y computadoras.

  1. Comience con la presentación más estrecha que deba soportar el contenido.
  2. Aumente gradualmente el ancho del viewport.
  3. Observe cuándo las líneas son demasiado largas, aparece espacio desperdiciado o los componentes pierden una relación adecuada.
  4. Introduzca un breakpoint únicamente en ese punto.
  5. Continúe ampliando y repita el proceso solo cuando sea necesario.

Enfoque rígido

@media (max-width: 480px) { ... }
@media (min-width: 481px) and (max-width: 768px) { ... }
@media (min-width: 769px) { ... }

Enfoque basado en contenido

/* Base estrecha */
.card { ... }

/* El cambio ocurre cuando la composición lo necesita */
@media (min-width: 42rem) { ... }

@media (min-width: 68rem) { ... }

Los valores concretos de los breakpoints pueden variar entre proyectos. La consistencia dentro de un mismo sistema de diseño es más importante que copiar puntos de corte de otro sitio.

Tipografía y espaciado responsivos

El texto debe seguir siendo legible en todo el rango de tamaños. Un error común consiste en relacionar el tamaño de fuente exclusivamente con vw. Esto puede producir texto demasiado pequeño o demasiado grande y puede interferir con el zoom del usuario.

Controlar la longitud de línea

Un contenedor que ocupa toda una pantalla grande puede producir líneas de texto demasiado largas. Un límite medido en caracteres permite mantener una medida de lectura razonable. 

p {
  max-width: 70ch;
}

Imágenes, video y contenido embebido

Los medios tienen dimensiones intrínsecas. Si son más anchos que su contenedor, pueden crear desplazamiento horizontal. Una regla base habitual es la siguiente. 

img,
video {
  max-width: 100%;
  height: auto;
  display: block;
}

iframe {
  max-width: 100%;
  display: block;
}

srcset y sizes

srcset permite ofrecer varias resoluciones del mismo recurso. sizes informa al navegador qué tamaño de visualización tendrá la imagen aproximadamente. El navegador elige el archivo adecuado según el espacio disponible y la densidad de pantalla. 

<img
  src="foto-960.jpg"
  srcset="foto-480.jpg 480w,
          foto-960.jpg 960w,
          foto-1440.jpg 1440w"
  sizes="(min-width: 70rem) 33vw,
         (min-width: 45rem) 50vw,
         100vw"
  width="960"
  height="640"
  alt="Estudiantes trabajando en un proyecto">

Los atributos width y height siguen siendo importantes incluso cuando la imagen cambia de tamaño con CSS. Permiten al navegador reservar la proporción necesaria antes de terminar la descarga y reducen cambios bruscos en el layout.

picture para dirección artística

picture es apropiado cuando no basta con cambiar la resolución y se necesita una composición distinta de la imagen para ciertos espacios. 

<picture>
  <source media="(max-width: 600px)" srcset="portada-recortada.jpg">
  <img src="portada-completa.jpg" alt="Edificio principal de la institución">
</picture>

Relaciones de aspecto

aspect-ratio permite reservar una proporción estable para tarjetas, videos o imágenes recortadas. 

.video {
  width: 100%;
  aspect-ratio: 16 / 9;
}

Container queries

Una media query responde al viewport. Esto es suficiente para cambios de layout globales, pero no siempre funciona bien con componentes reutilizables. Una tarjeta puede aparecer en una columna angosta dentro de una pantalla grande. En ese caso, el ancho del viewport no describe el espacio real de la tarjeta.

Las container queries permiten que los descendientes respondan al tamaño de un contenedor específico.

Responsive design no depende únicamente del ancho

Los dispositivos también difieren en forma de interacción y preferencias del usuario. Una interfaz no debería depender exclusivamente de un efecto hover, porque una pantalla táctil puede no tener un puntero preciso.

Consulta Uso
(hover: hover) El dispositivo principal puede mantener un estado hover.
(pointer: fine) El puntero principal tiene alta precisión, como un mouse.
(prefers-reduced-motion: reduce) El usuario ha indicado que prefiere menos movimiento.
(prefers-color-scheme: dark) El usuario prefiere una interfaz oscura. 
@media (hover: hover) and (pointer: fine) {
  .tarjeta:hover {
    transform: translateY(-2px);
  }
}

@media (prefers-reduced-motion: reduce) {
  * {
    scroll-behavior: auto;
    transition-duration: 0.01ms;
  }
}
Reordenar visualmente contenido con Grid o Flexbox no debe alterar una secuencia lógica de lectura. El orden del documento HTML sigue siendo importante para el teclado y para tecnologías de asistencia.

Problemas frecuentes de desbordamiento

Una página puede parecer responsiva y aun así generar desplazamiento horizontal debido a un único componente. Antes de añadir otra media query conviene identificar qué elemento está imponiendo el ancho.

Problema Causa habitual Posible corrección
Imagen fuera de pantalla Dimensión intrínseca mayor que el contenedor max-width: 100%; height: auto
Flex item que no se contrae Contenido largo y tamaño mínimo automático min-width: 0 en el elemento flexible
URL o palabra muy larga No existe un punto normal de salto overflow-wrap: anywhere
Tabla ancha Muchas columnas o contenido no reducible Contenedor con overflow-x: auto
Elemento con ancho fijo width mayor que el viewport Usar max-width, porcentajes o funciones de tamaño

Probar un diseño responsivo

Reducir manualmente la ventana es útil, pero no suficiente. Las herramientas de desarrollo permiten simular tamaños, densidades y orientación. Las pruebas en dispositivos reales siguen siendo necesarias cuando se quiere comprobar la interacción táctil, el teclado virtual, el rendimiento y diferencias específicas del navegador.

  1. Pruebe anchuras intermedias, no únicamente tamaños populares de dispositivos.
  2. Compruebe que no exista scroll horizontal accidental.
  3. Aumente el zoom del navegador y verifique que el contenido pueda reacomodarse.
  4. Pruebe textos más largos de los esperados y títulos que ocupen varias líneas.
  5. Revise la navegación con teclado y el orden lógico del contenido.
  6. Compruebe imágenes y recursos con una conexión limitada o mediante las herramientas de red.
  7. Pruebe al menos un dispositivo táctil real cuando el proyecto vaya a publicarse.
Un diseño responsivo no se considera terminado porque se ve bien en tres capturas. Debe conservar su estructura en el intervalo completo entre esos tamaños.

Proceso recomendado

  1. Declare correctamente el viewport.
  2. Construya HTML semántico con un orden lógico de lectura.
  3. Use una base fluida y limite los anchos máximos cuando sea necesario.
  4. Utilice Flexbox para que la estructura se adapte antes de añadir media queries.
  5. Haga que imágenes, video e iframes respeten sus contenedores.
  6. Diseñe primero para el espacio estrecho y agregue cambios al crecer el viewport.
  7. Seleccione breakpoints a partir del contenido, no de modelos de dispositivo.
  8. Controle tipografía y espacios con unidades relativas y límites explícitos.
  9. Use container queries cuando el comportamiento dependa del espacio de un componente.
  10. Pruebe el rango completo de anchuras, zoom, interacción y contenido variable.
