Un framework CSS construido sobre los mecanismos ya estudiados

Bootstrap es un framework CSS de código abierto que ofrece un sistema de rejilla, una colección de componentes de interfaz y un conjunto extenso de clases de utilidad. Su propósito es acelerar la construcción de sitios responsivos evitando que cada proyecto deba resolver desde cero problemas de distribución y de adaptación a distintos tamaños de pantalla que ya fueron estudiados mediante Flexbox, CSS Grid y las media queries.

Es importante notar que Bootstrap no reemplaza a CSS: internamente, sus clases están construidas con las mismas propiedades vistas hasta ahora. Un uso adecuado del framework requiere comprender qué hace cada clase, en lugar de aplicarla por ensayo y error.

La incorporación más sencilla de Bootstrap a un proyecto consiste en enlazar su hoja de estilos y, cuando se utilicen componentes con comportamiento propio (como los que se presentan más adelante), su paquete de JavaScript, ambos distribuidos mediante un CDN.

Bootstrap trabaja con un enfoque mobile first

Las reglas sin infijo se aplican desde el viewport más pequeño y continúan activas en los tamaños mayores. Los infijos sm, md, lg, xl y xxl agregan o reemplazan un comportamiento a partir de una anchura mínima. Por eso col-12 col-md-6 col-xl-4 se lee de izquierda a derecha como una progresión: ancho completo inicialmente, mitad desde md y un tercio desde xl.

Clase Desde Comportamiento que permanece activo
col-120 px (xs)12 de 12 columnas
col-sm-6576 px6 de 12 columnas
col-md-4768 px4 de 12 columnas
col-lg-3992 px3 de 12 columnas
col-xl-21200 px2 de 12 columnas
col-xxl-11400 px1 de 12 columnas

Los nombres sm o lg no describen un dispositivo concreto. Describen rangos de anchura CSS. Elija el cambio según el espacio que necesita el contenido, no según una marca de teléfono o tableta.

Contenedores

Todo el contenido que utiliza el sistema de rejilla de Bootstrap debe ubicarse dentro de un contenedor. La clase container centra el contenido y le asigna una anchura máxima distinta en cada punto de quiebre; la clase container-fluid, en cambio, ocupa siempre la totalidad del ancho disponible.

Sistema de rejilla y puntos de quiebre

Dentro de un contenedor, las filas, creadas con la clase row, agrupan horizontalmente a las columnas. Cada fila se divide en 12 unidades, y una columna declara cuántas de esas 12 unidades ocupa mediante clases como col-4 u col-md-4.

Una clase de columna sin infijo, como col-4, se aplica a partir de cualquier anchura. Al agregar un infijo correspondiente a un punto de quiebre, como en col-md-4, la regla solo se activa a partir de dicho punto de quiebre en adelante. Esto permite declarar distintos comportamientos según el tamaño de pantalla combinando varias clases en un mismo elemento, como en col-12 col-md-4.

Utilidades responsivas: display, orden y espaciado

El mismo patrón de infijos se usa fuera de la rejilla. Una utilidad sin infijo establece la regla inicial y otra con infijo la modifica desde un breakpoint. Por ejemplo, d-none d-md-block oculta un elemento inicialmente y lo muestra desde md; flex-column flex-lg-row cambia la dirección de un contenedor flexible desde lg.

Botones

La clase btn aplica el estilo base de un botón, y debe combinarse con una clase de color semántico, como btn-primary, btn-secondary, btn-success, btn-danger o btn-warning, entre otras. Anteponer btn-outline- al color produce la misma semántica con un estilo de contorno. El tamaño se ajusta con btn-lg o btn-sm.

La clase d-grid apila los botones a todo lo ancho en pantallas pequeñas, mientras que d-md-flex los coloca en una sola fila a partir del punto de quiebre md. Cambie btn-primary por btn-outline-primary en el botón central y observe la diferencia entre ambos estilos.

Tablas

La clase table aplica el estilo base de Bootstrap sobre un elemento table. Puede combinarse con table-striped para alternar el color de las filas, con table-bordered para mostrar bordes en todas las celdas, y con clases contextuales como table-success, table-warning o table-danger aplicadas a una fila o a una celda específica.

Con una anchura reducida, la tabla no se comprime ni oculta columnas: el elemento table-responsive le agrega una barra de desplazamiento horizontal propia, de modo que el resto de la página no se ve afectada. Aumente la anchura del marco y observe en qué punto la barra de desplazamiento deja de ser necesaria.

Barra de navegación

El componente navbar se combina con una clase navbar-expand-* que indica a partir de qué punto de quiebre se muestra expandida; por debajo de dicho punto, los enlaces se ocultan detrás de un botón de tipo hamburguesa. Este es el primer componente de la clase cuyo comportamiento depende del paquete de JavaScript de Bootstrap, y no únicamente de su hoja de estilos.

Ejemplo: navbar-expand-md
HTML
CSS

Con una anchura menor a 768px, los enlaces se ocultan y aparece el botón de hamburguesa; al hacer clic sobre él, el menú se despliega hacia abajo. Aumente la anchura del marco hasta superar 768px y observe que los enlaces se muestran directamente en la barra, sin necesidad del botón. Cambie navbar-expand-md por navbar-expand-lg y repita la prueba para notar que el punto de quiebre de la transición cambia.

Tarjetas

El componente card agrupa contenido relacionado dentro de un contenedor con borde. Para distribuir varias tarjetas de forma responsiva, se combinan con la clase row y con row-cols-*, que definen cuántas tarjetas se muestran por fila en cada punto de quiebre.

Ejemplo: row-cols-1 row-cols-md-2 row-cols-lg-4
HTML
CSS

Reduzca la anchura del marco y observe que las cuatro tarjetas se apilan en una sola columna. Auméntela hasta superar 768px para ver dos tarjetas por fila, y hasta superar 992px para ver las cuatro en una sola fila. El número que sigue a row-cols- indica directamente cuántos elementos se distribuyen por fila.

Imágenes fluidas y contenido con proporción

Una imagen con dimensiones intrínsecas mayores que su contenedor puede provocar desbordamiento. La clase img-fluid aplica max-width: 100% y height: auto, de modo que la imagen se reduce sin deformarse. Para video, mapas o contenido embebido, ratio reserva una proporción estable como ratio-16x9, ratio-4x3 o ratio-1x1.

Pruebas y depuración de una interfaz Bootstrap

Probar únicamente 375, 768 o 1200 px no basta. Los breakpoints son puntos de transición, pero los errores suelen aparecer entre ellos: textos largos, traducciones, zoom, tablas, imágenes o controles que ya no caben. Arrastre el borde de cada resultado lentamente y compruebe también unos píxeles antes y después de cada breakpoint.

  1. Comience en una anchura pequeña y confirme que no exista desplazamiento horizontal global.
  2. Recorra todas las anchuras, no solo los presets, y observe cuándo el contenido pide un cambio.
  3. Pruebe la navegación con teclado y verifique foco visible, orden lógico y controles con nombre accesible.
  4. Aumente el zoom al 200 % y use textos más largos para descubrir cortes o solapamientos.
  5. Inspeccione qué clase gana en cada breakpoint antes de agregar CSS personalizado.

Las clases responsivas reducen CSS repetitivo, pero no sustituyen las decisiones de diseño ni las pruebas con contenido real.
